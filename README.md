# سجل التدريب التعاوني — دليل الإعداد والنشر

موقع شخصي لتسجيل مهامك اليومية خلال التدريب التعاوني (٦ أشهر: GRC → Blue Team → Red Team)
وتوليد تقارير أسبوعية وشهرية وتقرير ختامي ثنائي اللغة (عربي/إنجليزي).

---

## الخطوة ١: إنشاء مشروع Firebase (مجاني)

1. روح لـ https://console.firebase.google.com
2. سجّل دخول بحساب Google → **Add project** → اكتب اسم زي `coop-training-log`
3. عطّل Google Analytics (مو ضروري) → **Create project**

### تفعيل تسجيل الدخول
4. من القائمة الجانبية: **Build → Authentication → Get started**
5. فعّل **Email/Password** كطريقة دخول → **Save**

### تفعيل قاعدة البيانات
6. من القائمة الجانبية: **Build → Firestore Database → Create database**
7. اختر **Start in production mode** → اختر أقرب موقع سيرفر (مثل `eur3` أو `me-central1` إذا متاح) → **Enable**

### تحديث قواعد الحماية (Security Rules)
8. من تبويب **Rules** داخل Firestore، استبدل المحتوى بالتالي، ثم **Publish**:

```
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    match /users/{userId}/{document=**} {
      allow read, write: if request.auth != null && request.auth.uid == userId;
    }
  }
}
```

هذا يضمن إن بياناتك تُقرأ وتُكتب فقط من حسابك أنت.

### الحصول على مفاتيح الربط
9. من ⚙️ **Project settings** (بجانب Project Overview) → انزل لـ **Your apps** → اضغط أيقونة الويب `</>`
10. اكتب اسم للتطبيق (مثل `coop-web`) → **Register app**
11. بيظهر لك كائن `firebaseConfig` فيه القيم — انسخها

---

## الخطوة ٢: تعبئة المفاتيح في المشروع

افتح ملف `js/firebase-config.js` واستبدل القيم التالية بالقيم اللي نسختها من Firebase:

```js
const firebaseConfig = {
  apiKey: "...",
  authDomain: "...",
  projectId: "...",
  storageBucket: "...",
  messagingSenderId: "...",
  appId: "..."
};
```

> ملاحظة أمنية: مفاتيح Firebase هذي مصممة تكون ظاهرة في كود الواجهة الأمامية (client-side) — الحماية الفعلية موجودة في Security Rules اللي ضبطناها في الخطوة السابقة، مو بإخفاء المفتاح.

---

## الخطوة ٣: النشر على GitHub Pages

1. روح لحسابك على GitHub → **New repository** → اسم زي `coop-training-log` → Public → Create
2. ارفع كل ملفات المجلد (`index.html`, `css/`, `js/`) للـ repo:
   - إما بالسحب والإفلات من واجهة GitHub مباشرة (Add file → Upload files)
   - أو عبر Git:
     ```
     git init
     git add .
     git commit -m "Initial commit"
     git branch -M main
     git remote add origin https://github.com/USERNAME/coop-training-log.git
     git push -u origin main
     ```
3. من الـ repo: **Settings → Pages**
4. تحت **Source** اختر branch `main` والمجلد `/ (root)` → **Save**
5. بعد دقيقة أو دقيقتين بيصير موقعك متاح على:
   `https://USERNAME.github.io/coop-training-log/`

---

## الخطوة ٤: أول استخدام

1. افتح الرابط → اضغط **إنشاء حساب لأول مرة** بأي بريد وكلمة مرور تختارها (هذا حسابك الشخصي بالموقع، منفصل عن بريدك الحقيقي، بس تقدر تستخدم بريدك العادي)
2. بعدها روح لصفحة **الإعدادات** واملأ بياناتك (الاسم، الرقم الجامعي، الجهة، المشرف، تاريخ بداية التدريب)
3. ابدأ تسجيل مهامك اليومية من صفحة **تسجيل مهمة**

من أي جهاز ثاني (جوال، لابتوب) — افتح نفس الرابط وسجّل دخول بنفس البريد وكلمة المرور، وبتلقى نفس بياناتك.

---

## ملاحظات مهمة

- **النسخة الاحتياطية**: من صفحة الإعدادات فيه زر "تصدير نسخة احتياطية (JSON)" — استخدمه بشكل دوري (أسبوعيًا مثلاً) للاطمئنان.
- **الطباعة/PDF**: في كل صفحة تقرير فيه زر "طباعة / حفظ PDF" يفتح نافذة طباعة المتصفح — اختر "Save as PDF" للحصول على ملف جاهز للتسليم.
- **الهوية البصرية**: زر "الهوية البصرية" في القائمة الجانبية يبدّل بين ثيم أمن سيبراني تقني غامق وثيم أكاديمي بألوان جامعية (أخضر/ذهبي) — عدّل الألوان في `css/style.css` (متغيرات `body[data-theme="university"]`) إذا حبيت تطابقها بالضبط مع هوية جامعتك.
- **الملخص التنفيذي بدون AI**: التقارير حاليًا تُبنى تلقائيًا من بياناتك (إحصائيات + جداول + فقرة ملخص تلقائية) بدون استدعاء نموذج ذكاء اصطناعي، لأن أي مفتاح API لخدمة AI يظهر في كود الواجهة الأمامية يكون غير آمن على موقع عام. إذا حبيت لاحقًا ملخص تنفيذي مكتوب بأسلوب أكثر احترافية عبر AI، الحل الآمن هو إضافة Firebase Cloud Function تستدعي الـ API من السيرفر — قابل للإضافة لاحقًا لو تبي.

## ميزات إضافية

- **المهام الممتدة لعدة أيام**: عند تسجيل مهمة، فيه حقل "تاريخ الانتهاء" اختياري — إذا تركته فاضي، المهمة تُحسب ليوم واحد فقط. إذا حددت تاريخ انتهاء، المهمة تظهر تلقائيًا في كل تقرير أسبوعي/شهري تتقاطع معه فترتها.
- **الرئيسية (Dashboard)**: أول صفحة تفتح عليها — فيها إحصائيات سريعة، رسم بياني لعدد المهام آخر ٨ أسابيع، توزيع حسب المرحلة (GRC/Blue/Red)، وشبكة "أيام التسجيل" للشهر الحالي مع عداد الأيام المتتالية.
- **الترويسة الرسمية (Letterhead)**: كل تقرير (أسبوعي/شهري/ختامي) يبدأ بترويسة فيها اسم الجامعة/الكلية (من الإعدادات) واسمك ورقمك الجامعي والمشرف وتاريخ الإصدار. الشعار حاليًا حرف مبدئي بسيط — عند إرسالك القالب الرسمي للجامعة نضبط الترويسة لتطابقه بالضبط.
- **المهام والمواعيد**: صفحة مستقلة لتخطيط مهام التدريب قبل تنفيذها (غير سجل المهام اليومي) — فيها كانبان (لم أبدأ / قيد التنفيذ / منجزة)، وقائمة مرتبة حسب الموعد والأولوية، وتقويم شهري لمواعيد التسليم. لما تنقل مهمة لعمود "منجزة"، تتحول تلقائيًا لسجل يومي بتاريخ اليوم في صفحة "تسجيل مهمة" — بدون ما تمسح أي مهام فعلية مسجلة بنفس اليوم.
